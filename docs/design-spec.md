# moonx — 設計仕様書

> **地方で地元ビジネスを始めたい人が、自己分析からアイデア検証、ビジネスプランまでを、スマホとWebで迷わず進められる起業検討アプリ。**

- 入力: `docs/concept.md`（Phase 0）、`docs/brainstorm-notes.md`（Phase 1）、Phase 2 の深掘りでの合意（9.1）
- 画面遷移図: `docs/screen_flow.mermaid`（別紙）
- この文書は画面・UX の正（生きたソース）。データモデル章（7章）は Phase 3 で System Design Doc に移る

## 1. プロダクト概要

### 1.1 コンセプト

BCDX は「自己分析 → アイデア検証 → ビジネスプラン」の手順を Google Docs / Sheets のテンプレートで回している。moonx はこの手順をそのままアプリにし、次の3つの負担をなくす。

| 現行の負担 | moonx での解決 |
|---|---|
| 工程間の転記と全体把握（検証の数字や顧客・課題をプランへ手で写す。複数アイデア・複数メンバーの進み具合を一覧できない） | 検証で Proceed にしたアイデアは、主要な数字・顧客・課題がプランの下書きに引き継がれる。数字の正は検証に置き、プランは常に検証を参照する。ダッシュボードでアイデアとメンバーの状況を一覧する |
| 検証の抜け漏れ（最低限の確認項目と Fact / Assumption / Unknown の区別がどこまで済んだか分からない） | 必須の確認項目6つを入力内容から自動で判定し、F/A/U の内訳と一緒に「足りないもの」を状態として示す。点数は付けない |
| スマホでの入力（結合セルの多い表や長いドキュメントをモバイルから埋めにくい） | スマホでは自己分析も検証も1問ずつカードで答える。表は行ごとのカードにする。スマホで少しずつ進め、続きは Web の大きな画面で開ける |

提供する体験の柱:

1. **1問に集中して答える**: 自己分析（36問）・検証の設問（01 / 02 / 10 など）・プランの30項目を、テンプレートの EXAMPLE をヒントにして書く。スマホは1問ずつのカード、Web はセクションの設問を縦に並べ、入力中の設問が画面の中央に来る
2. **その場で計算する**: コストと価格を入れると、損益分岐・4シナリオ（Conservative / Expected / Strong / Capacity Limit）・投資回収・ROI がその場で出る。未入力は「未入力」、粗利のマイナスは警告で示す
3. **足りないものが見える**: 確認項目6つの状態と F/A/U の内訳。点数やランキングは出さない
4. **プランへつながる**: Proceed で下書きを作り、版を保存し、Go / No-Go を記録し、実行管理と Pitch Deck まで進める
5. **外部の AI と往復できる**: 設問・回答・対話用プロンプトを Markdown / JSON で書き出し、AI で整理した結果を貼り付けて取り込む。AI はアプリに組み込まない

### 1.2 プロダクト方針

| 項目 | 方針 |
|---|---|
| 目的 | BCDX が Drive での運用を丸ごと置き換えて使い込み、そのまま一般公開へ広げる |
| スコープ | フル機能。3工程の入力・計算・進捗の可視化・プランへの引き継ぎに加え、AI 往復（書き出し・取り込み）、プランの実行管理、決定ログとコメント、Pitch Deck、すべての変更履歴、運営者の管理画面 |
| 公開範囲 | 初期リリースは招待制（BCDX のみで試運転）。設計は一般公開を前提にする。誰でも登録できる受付は一般公開のときに開く |
| 収益化 | 保留。当面は無料を前提に設計する |
| デバイス | スマホと Web の両方で、全画面を使える。書く画面はスマホを基準に、数字と表の画面は Web を基準に設計し、どちらでも欠けなく操作できるようにする |
| **対応言語（UI）** | **英語のみ**。ただし多言語化できる作りは残す（UI の文言はすべてコードから分けて管理し、日付・数値・通貨は書式を切り替えられるようにする） |
| 対応言語（回答） | 自由（英語・タガログ語・Hiligaynon・日本語・混在など）。アプリは回答を翻訳しない。日本語を含む多言語の文字を表示できること |
| 通貨 | ワークスペースごとに設定し、既定は PHP。複数通貨の換算はしない |
| AI | アプリに組み込まない。外部の AI（ChatGPT・Claude など）との往復（書き出し・取り込み）だけを支える |
| 通知 | アプリ内のみ。メール通知は一般公開のときに検討する。ただし招待とパスワード再設定のメールは送る（認証に必要な連絡で、通知とは別） |
| 既存データ | Google Drive の既存データ（自己分析1件、記入済みの検証1件）は手で入れ直す。Drive からの取り込み・同期・書き出しは作らない |
| 変更履歴 | 検証・プラン・実行管理・自己分析のすべての変更を項目単位で残し、差分を見て元に戻せる |
| テンプレート | 設問・EXAMPLE・確認項目の基準値・費用行の初期値・実行管理の初期行・AI 用プロンプトは運営者がアプリ内で編集し、版として公開する。既存の回答は作成時の版に固定する |

### 1.3 UI設計原則

| 原則 | 内容 |
|---|---|
| 1問に集中する | 書く画面では、入力中の1問（または1行）に意識を集める。スマホは1画面に1問、Web はセクションを見渡しつつ入力中の問いを中央に置く。いつ閉じても自動保存され、「続きから」で最初の未回答に戻れる |
| 点数を付けない | 合計点・ランキング・採点の色分けは出さない。足りないものを「未着手 / 途中 / 達成」「F/A/U の内訳」という状態で示す。アイデア一覧は判定順に並べない（既定は更新順。「勝者を早く決めない」原則） |
| 未入力と 0 を区別する | 値がない欄は「未入力」と表示し、計算できないときは何が足りないかを書く。0 は 0 として扱う。粗利のマイナスや Capacity 超過は警告で示し、隠さない |
| 数字の正は1か所 | 数字は検証（17 費用・18 損益・シナリオ）でだけ編集する。プランと Pitch Deck は参照表示で、数字の横に「検証で直す」リンクを置く |
| 保存ボタンを置かない | 入力が止まったら自動で保存し、保存状態（保存中 / 保存済み / 保存できませんでした）を常に表示する。すべての保存は変更履歴に残る |
| どこでも同じ部品 | 設問フォーム・F/A/U の付け方・根拠シート・コメントパネル・変更履歴パネルを全工程で共通にする。一度覚えれば全工程で使える |
| できない操作は出さない | 権限のない操作（Viewer の編集・判定・AI 往復など）のボタンは無効化ではなく非表示にする |
| 押し付けない | 起業を答えとして押し付けない（README の原則）。AI や「次のおすすめ」は進め方を示すだけで、アイデアの良し悪しは言わない |

### 1.4 用語と UI 表記

UI は英語なので、仕様書の用語と画面に出す英語表記を対応させる。

| 仕様書の用語 | UI 表記 | 意味 |
|---|---|---|
| ワークスペース | Workspace | チーム（または個人）の単位。アイデア・プランはワークスペースに属する |
| 自己分析 | Self Analysis | 1人に1つ。ワークスペースには属さず、本人が共有先を選ぶ |
| アイデア | Idea | 検証とプランの親。1アイデアに1検証、0個以上のプラン |
| 検証 | Validation | 原本「Business Idea & Validation」の 00〜10 |
| プラン / 案 | Business Plan / Plan A, Plan B | 原本「Business Plan」。1アイデアに複数の案を持てる |
| 項目 / 小項目 | Item / Prompt | プランの30項目と、各項目の中の問い（例: §1 の「What is the business?」） |
| 判定 | Decision | Proceed / Hold / Drop |
| Go / No-Go | Go / No-Go | プランの決定。立ち上げ（Launch）/ 延期（Delay）/ 中止（Stop） |
| 工程 | Stage | 検証（Validation）/ プラン（Planning）/ 立ち上げ準備（Launch prep）。自動で決まる |
| 確認項目 | Checks | 必須の確認項目6つ。状態は 未着手（Not started）/ 途中（Partial）/ 達成（Done） |
| F/A/U | Fact / Assumption / Unknown | 回答と数字の分類。加えて 未分類（Unclassified）・未入力（Empty） |
| 確信度 | Confidence | Low / Medium / High。Assumption だけに付ける |
| 根拠 | Evidence | Fact に必須。調査ログの項目か URL |
| 調査ログ | Research Log | 原本 03 |
| 裏付ける確認項目 | Supports check | 調査ログに付けるタグ。地元の価格帯（Local price）/ 許認可（Permits）/ 需要・課題シグナル（Demand or problem signal） |
| 版（プラン） | Version | プラン全体の名前付きスナップショット（例: 「v1 For advisors」）。人が「版を保存」したときだけ作られる |
| 変更履歴 | History | 項目ごとの全変更の記録 |
| 決定ログ | Decision Log | 判定・Go / No-Go・版の保存の記録 |
| 次のおすすめ | Next steps | 検証ホームが示す、次に埋めると良いもの |
| AI 書き出し / AI 取り込み | Export for AI / Import from AI | 外部の AI との往復 |

## 2. ユーザーロールとフロー

### 2.1 ロール定義

| ロール | 区分 | 概要 | 主な操作 |
|---|---|---|---|
| 運営者（Admin） | アプリ全体 | アプリの管理者。ワークスペースのロールとは別の区分。自分の個人用ワークスペースも持つ | テンプレートの編集と公開（設問・EXAMPLE・確認項目の基準値・費用行と実行管理の初期行・AI 用プロンプト）。ユーザーとワークスペースの管理（一覧・利用状況・停止）。招待の発行 |
| Owner | ワークスペース | ワークスペースの管理者。登録時に自動で作られる個人用ワークスペースでは本人が Owner | Member の全権限。加えて、メンバーの招待・削除・ロール変更と、ワークスペース名・通貨の設定 |
| Member | ワークスペース | 共同創業者 | アイデア・検証・プラン・実行管理の作成と編集、判定・Go / No-Go・版の保存、コメント、AI 往復、アイデアの複製。自分の自己分析の共有と、共有された自己分析の閲覧 |
| Viewer | ワークスペース | アドバイザーや出資候補 | アイデア・検証・プラン・実行管理・Pitch Deck・決定ログの閲覧とコメント。自己分析は共有済みでも見られない |
| 本人 | 自己分析 | 自己分析の持ち主 | 自分の自己分析の編集・完了・共有・AI 往復・変更履歴の閲覧 |

- 1人のユーザーが複数のワークスペースに所属できる。ロールはワークスペースごとに持つ。
- 自己分析は1人に1つ。本人が共有するまで本人だけが見られる。共有先のワークスペースは本人が選ぶ。共有先で見られるのは Owner / Member だけ。
- 判定と Go / No-Go は Member 以上なら誰でも記録できる。投票や承認の仕組みは作らない。誰が・いつ・なぜ決めたかを決定ログに残す。
- 運営者は、ワークスペースに所属していなければその中身（アイデア・検証・プラン）を見られない。管理画面で見えるのは件数や最終利用日などの利用状況だけ。

### 2.2 権限マトリクス

○ = できる、— = できない（ボタンを出さない）。

| 操作 | Owner | Member | Viewer | 備考 |
|---|---|---|---|---|
| ダッシュボード・アイデア・検証・プラン・実行管理・Pitch Deck・決定ログの閲覧 | ○ | ○ | ○ | |
| アイデアの作成・複製・アーカイブ | ○ | ○ | — | |
| 検証・プラン・実行管理の編集 | ○ | ○ | — | |
| 判定・プラン下書きの作成・版の保存・Go / No-Go の記録 | ○ | ○ | — | |
| コメント（書く・返信・メンション） | ○ | ○ | ○ | 自分のコメントだけ編集・削除できる |
| 変更履歴の閲覧 | ○ | ○ | ○ | 自己分析の履歴は本人だけ |
| 変更履歴から元に戻す | ○ | ○ | — | |
| AI 書き出し・取り込み（検証・プラン） | ○ | ○ | — | |
| 自分の自己分析の編集・共有・AI 往復 | ○ | ○ | ○※ | ※自己分析はワークスペースに属さない。Viewer として所属するワークスペースを開いている間は自己分析タブを出さないが、自分が Owner の個人用ワークスペースからは使える |
| 共有された自己分析の閲覧・コメント | ○ | ○ | — | |
| ワークスペース名・通貨の変更、招待、ロール変更、メンバー削除 | ○ | — | — | 最後の Owner は自分を降格・削除できない |
| テンプレート・ユーザー・ワークスペースの管理、招待の発行 | — | — | — | 運営者（Admin）だけ |

### 2.3 フロー全体像

```
共通:      招待リンク → 2 新規登録 → 3 オンボーディング → 5 ダッシュボード
           1 ランディング → 2 ログイン → 5 ダッシュボード（最後に開いたワークスペース）

Member（コアフロー: アイデアを検証して判定する）:
           6 アイデア一覧 → M1 新しいアイデア → 13 検証ホーム
           → 11 設問フォーム / 14 調査ログ / 15 競合・代替 / 16 前提・リスク / 17 費用 / 18 損益・シナリオ（順番は自由）
           → （行き詰まったら）24 AI 書き出し → 外部の AI → 25 AI 取り込み → 元の画面
           → 13 検証ホームで不足と Unknown を確認 → 19 判定
           → Proceed: M5 プラン下書きの作成 → 20 プランホーム
             Hold: 後で 13 から再開して判定し直す / Drop: 一覧では既定で隠れる（再判定できる）

Member（プラン）:
           20 プランホーム → 21 プラン項目の編集 → M3 版の保存 → M4 Go / No-Go
           → 22 実行管理 → 23 Pitch Deck（1分版 / 5分版、PDF 書き出し）

Member（自己分析）:
           10 自己分析ホーム → 11 設問フォームで答える → （24 / 25 で AI 往復）→ 完了
           → M6 共有先を選ぶ → チームの Owner / Member が 12 で読んでコメント

Viewer:    5 ダッシュボード → 6 アイデア一覧 → 13 検証ホーム（閲覧）→ 20 プランホーム → 23 Pitch Deck
           どの画面でもコメントできる

Owner:     Member のフロー + 9 ワークスペース設定（名前・通貨・招待・ロール）

Admin:     26 テンプレート一覧 → 27 テンプレート編集 → 新しい版として公開
           28 ユーザーとワークスペース → 招待の発行・ユーザーの停止
```

- 設問の入力欄に入る（クリック・タップ・Tab）と、その設問が画面の中央へなめらかにスクロールする。

- ヘッダーの「Focus」スイッチで、全設問を開いた状態にも切り替えられる（既定はフォーカスあり。選択は端末に覚えておく）。

### 4.3 レスポンシブ方針

| ブレイクポイント | 幅 | 対応 |
|---|---|---|
| デスクトップ | ≥1024px | 左にサイドバー（ワークスペース切替・ナビ・ユーザーメニュー）を常に出す。パターン A・D・F は2カラム。コメント / 変更履歴パネルは右のパネルで、本文の入力を閉じずに読める |
| タブレット | 768〜1023px | サイドバーはアイコンだけに縮める。2カラムのパターンは、右側を折りたたみかオーバーレイにする。パネルはオーバーレイ。設問フォームは Web と同じ縦並び |
| モバイル | <768px | 下のタブ（Dashboard / Ideas / Self Analysis / Notifications）と「More」メニュー。1カラム。設問は1問ずつのカード。表は行ごとのカードにし、横スクロールさせない。編集・パネル・モーダルは下からのボトムシートか全画面シート。主要な操作は下部に固定する |

共通の決まり:

- タップ領域は 44px 以上。
- スマホでは結合セルのような大きな表を出さない。行はカードにし、1行の編集はシートで行う（原本の「スマホで埋めにくい」を解消する）。
- スマホのキーボード表示中も、入力欄と保存状態が隠れないようにする。

### 4.4 ビジュアルデザイン方針

具体的な値（色の HEX・フォント名・余白）は Phase 3 の `docs/06_design-tokens.json` で決める。

| 項目 | 方針 |
|---|---|
| トーン&ムード | **Hermes Agent（Nous Research）のような雰囲気**。深いティールとクリームの落ち着いた配色に、見出しだけ少しレトロな個性を出す。演出で煽らず、点数や派手な達成表現は使わない |
| カラーの方向性 | **Hermes Agent の既定テーマ「Hermes Teal」系**。ダーク: 深いティールの背景、クリームの文字と罫線、金色はごく控えめなアクセント（ブランドと主要な操作だけ）。ライト: クリームの背景に深いティールの文字。これとは別に意味色を用意する: F/A/U と 未分類（4色。未入力はグレー）、確認項目の状態（未着手・途中・達成）、警告（粗利マイナス・Capacity 超過・保存失敗）。判定（Proceed / Hold / Drop）は勝ち負けに見えないよう控えめな色にし、Drop を危険色（赤）にしない。金色のアクセントと「途中」の色は区別できるようにする。色だけで意味を伝えず、必ずラベルかアイコンを添える（WCAG AA のコントラスト） |
| タイポグラフィの方向性 | **見出しだけ個性的な書体**。Hermes のサイトのように、見出し・ロゴ周りだけレトロな表示用書体にし、本文・回答・入力欄・表はシステムのサンセリフにする。回答にタガログ語・Hiligaynon・日本語が混ざるため、日本語を含む多言語を表示できる代替フォントを必ず用意する（表示用書体に日本語が無い場合も、見出しが崩れないようにする）。数字（表・指標・金額）は等幅数字にして桁をそろえる。金額は通貨記号と桁区切りを付ける。長文の回答は行間を広めにする。背景の粒子やグローなどの質感は使わない |
| ライト/ダークモード | **両対応（OS 追従＋手動切替）**。既定は OS の設定に従い、4 アカウント設定で System / Light / Dark を選んで固定できる（夜にスマホで少しずつ進める使い方に合わせる）。意味色はどちらのモードでも区別できるように両方の値を用意する。**Pitch Deck の PDF は常にライト** |
| 情報密度 | **画面で使い分け**。設問フォーム・判定・プラン項目など書く画面はゆったり（考えるための余白）。費用・損益・調査ログ・一覧・ダッシュボードなど表と数字の画面は中密度（比べて読むため）。スマホは全体を一段ゆったりにする |

## 5. 画面遷移

別紙の `docs/screen_flow.mermaid` を参照。

分岐条件と補足:

- **認証**: ログインなしで開けるのは 1・2 と招待リンクだけ。ログインしていない状態で他の画面の URL を開くと 2 へ移り、ログイン後に元の画面へ戻る。
- **新規登録**: 招待リンク経由に限る。招待はワークスペースの Owner（9）か運営者（28）が出す。
- **登録時**: 個人用ワークスペースを自動で作る（本人が Owner、名前は「{表示名}'s workspace」、通貨 PHP。9 で後から変えられる）。招待元のワークスペースがあれば、招待で指定されたロールで所属する。
- **ログイン後**: 最後に開いたワークスペースの 5 へ進む。初回は招待元のワークスペース（なければ個人用）。ワークスペースは M7 で切り替える。
- **共通ナビ**: スマホは下のタブ、Web は左のサイドバー。
  - タブ: 5 Dashboard / 6 Ideas / 10 Self Analysis / 8 Notifications（未読数のバッジ）
  - メニュー（More）: 7 Decision Log / M7 ワークスペース切替 / 4 Account / 9 Workspace Settings（Owner）/ 26 Admin（Admin）/ ログアウト
- **Viewer**: 編集ボタン、19 判定、M3 / M4 / M5、24 / 25 の AI 往復、自己分析タブ（10〜12）を出さない。
- **12** に出るのは、今のワークスペースに共有済みの自己分析だけ。
- **検証の中の移動**: 14〜18 と 11（検証の設問）のヘッダーにセクション切替を置き、13 に戻らずに隣のセクションへ移れる。
- **25 で反映した後**は、書き出し元の画面（10 / 11 / 13 / 20 / 21）へ戻る。
- **Fact の根拠**は、入力中の画面から M2 で付ける。既存の調査ログから選ぶか、新しく追加する。追加したものは 14 にも残る。
- **プラン下書き**は、最新の判定が Proceed のときだけ作れる（19 の直後、または 13 / 20 の「Add plan」）。Hold のアイデアは後で判定し直せる。Drop のアイデアは 6 と 5 で既定では隠れ、絞り込みで出せる。編集と再判定はいつでもできる。
- **21 では引き継いだ数字を直せない。** 数字の横の「検証で直す」から 17 / 18 へ移る。数字の違う案は、6 で「アイデアを複製」して別の検証として作る。
- **通知・決定ログからの移動**: 通知は該当の項目（コメントならパネルを開いた状態）へ、決定ログは 13 か 20 へ移る。

#### 6.0.2 自動保存と同時編集

- **保存のタイミング**: 文字入力が約1秒止まったとき、入力欄から離れたとき、画面を離れるとき。選択式（F/A/U・確信度・選択の設問など）は選んだ時点で保存する。
- **保存状態**: ヘッダーに「Saving… / Saved / Couldn't save — Retry」を出す。
- **保存できなかったとき**: 入力内容は端末に残し、自動で再試行する。オフラインのときは画面上部に「Offline — changes will be saved when you reconnect」を出し、再接続したら送る。オフラインでの新しい画面の閲覧は対象外。
- **同時編集**: 保存の単位は項目（1つの回答・1つの行・1つの数字）。開いた後に他の人が同じ項目を保存していた場合は、保存の前に「Paolo updated this answer 3 minutes ago」と出し、「相手の内容を読み込む」「自分の内容で上書きする」から選ばせる。どちらを選んでも、両方の内容が変更履歴に残る。
- **変更履歴**: 保存のたびに、誰が・いつ・どの項目を・変更前 → 変更後を記録する（6.0.5）。

#### 6.0.3 F/A/U の付け方と根拠シート（M2）

対象: 検証の設問への回答（01 / 02 / 04 のパターン / 08 / 10）と、検証の数字（費用行の金額、価格・営業日数・目標利益率・4シナリオの1日の販売数）。自己分析とプランの回答には付けない。

| 状態 | 条件 | 表示 |
|---|---|---|
| 未入力 | 値がなく、F/A/U も付いていない | グレーの「Empty」 |
| 未分類 | 値はあるが、F/A/U が付いていない（AI 取り込みで内容が変わった回答もここに戻る） | 「Unclassified」 |
| Fact | 値があり、根拠が1件以上ある | 「Fact」＋根拠のチップ |
| Assumption | 値があり、確信度（Low / Medium / High）が付いている | 「Assumption · Medium」 |
| Unknown | 分からないと分かっている。文章の回答は、何が分からないかを書いてもよい。**数字は値を持たない** | 「Unknown」 |

入力欄の下に3つのボタン `[Fact] [Assumption] [Unknown]` を並べる。

- **Fact** を押すと M2 を開く。根拠を1件以上付けると Fact になる。根拠を付けずに閉じたら、元の状態に戻す（根拠のない Fact を作らない）。
- **Assumption** を押すと、その場に確信度の選択（Low / Medium / High）を出す。選ぶまでは確定しない。
- **Unknown** を押すと Unknown になる。数字に値が入っているときは「値を消して Unknown にしますか？ 値を残すなら Assumption（確信度 Low）を選んでください」と確認する。
- もう一度同じボタンを押すと外れる（値があれば 未分類、なければ 未入力 に戻る）。
- 値を消すと F/A/U も外れて 未入力 に戻る（Unknown は除く）。

**M2 根拠シート**:

```
┌ Evidence ─────────────────────────────── × ┐
│ 対象: 01 WHO — Who exactly is the customer?  │
│                                             │
│ 付いている根拠                                 │
│  [📄 2026-09-12 Store observation: SM…  ×]  │
│  [🔗 https://psa.gov.ph/…               ×]  │
│                                             │
│ ( 調査ログから選ぶ ) ( 新しく記録する ) ( URL )  │
│  🔍 検索…                                    │
│  ☐ 2026-09-14 Price check: Lacson St. …     │
│  ☐ 2026-09-10 Google Maps reviews …        │
│                                [ 完了 ]      │
└─────────────────────────────────────────────┘
```

- 「調査ログから選ぶ」: このアイデアの調査ログを検索して複数選べる。
- 「新しく記録する」: 14 と同じ入力欄（日付・トピック・発見・出典の種類・URL・裏付ける確認項目・何を裏付けるか）で調査ログを1件作り、そのまま根拠に付ける。作った項目は 14 にも残る。
- 「URL」: 調査ログを作らずに URL とメモだけを付ける（原本の実例で、外部の Google Doc へのリンクを根拠にしていたため）。
- 根拠に使われている調査ログを 14 で削除しようとすると、使っている項目の一覧を出して確認する。削除すると、その根拠しかなかった Fact は「根拠なし」の警告状態になり、13 の次のおすすめに出る。

#### 6.0.4 コメントパネル（PNL-1）

- 対象: 10〜23 の各項目（設問の回答・リストの行・費用行・数字・プランの小項目・実行管理の項目・スライド）。コメントの数を項目の横にバッジで出す。
- Web は右のパネル（本文の入力を閉じずに読める）、スマホは下からのボトムシート。
- スレッド: コメントと返信（1段まで）。`@` でワークスペースのメンバーをメンションできる（Viewer も含む）。自分のコメントは編集・削除できる（削除は「deleted」と残す）。スレッドは「解決」にでき、解決済みは折りたたむ。
- 自己分析へのコメントは、共有先のワークスペースごとに分かれる。本人には、どのワークスペースからのコメントかを表示する。共有をやめるとそのワークスペースのコメントは見えなくなり、共有し直すと戻る。
- 空の状態: 「No comments yet」と入力欄。
- 書き込みに失敗したら、入力内容を残して「Couldn't post — Retry」。

#### 6.0.5 変更履歴パネル（PNL-2）

- 対象: 10〜22 の各項目と、画面全体（その画面の全項目の履歴をまとめて表示）。出し方はコメントパネルと同じ（Web は右のパネル、スマホはボトムシート）。
- 1件ごとに、誰が・いつ・どの項目・変更前と変更後の差分（文字単位の強調）・変更の種類（手入力 / AI 取り込み / 元に戻す / テンプレートの移行 / 複製 / 下書き作成）を出す。
- 「この時点に戻す」で、その時点の値に戻す。戻すこと自体も新しい変更として履歴に残る。削除した行は「削除を取り消す」で戻せる。
- 自己分析の履歴は本人だけが見られる。共有先のメンバーには履歴ボタンを出さない。
- Viewer は見られるが、戻せない。
- 空の状態: 「No changes yet」。

#### 6.0.6 共通の状態表示

| 状態 | 表示 |
|---|---|
| ローディング | その画面のレイアウトの形をした骨組み（スケルトン）。10秒を超えたら「Taking longer than usual」と再試行ボタン |
| 読み込みエラー | 本文の位置に「Couldn't load this page」と再試行ボタン。ナビは使えるままにする |
| 権限がない | 「You don't have access to this」とダッシュボードへのリンク（他のワークスペースの URL を開いたときなど） |
| 見つからない | 「Not found. It may have been archived.」とアイデア一覧へのリンク |
| 保存エラー | 6.0.2 のとおり、項目の横とヘッダーに出す |
| 空（0件） | その画面が何をする場所かを1〜2行で説明し、権限があれば最初の操作のボタンを出す。Viewer には説明だけを出す |

#### 6.0.7 テンプレートの版と移行（M8）

- 自己分析・検証・プランは、作った時点で公開されている最新の版を参照する。運営者が新しい版を公開しても、既存の回答は変わらない。
- 新しい版があるとき、10 / 13 / 20 のヘッダーに「A newer template is available」を出す（Owner / Member、自己分析は本人だけ）。
- M8 で移行すると、設問 ID が一致する回答を引き継ぐ。移行の前に、引き継げない回答（新しい版にない設問）の一覧を出す。引き継げない回答は消さずに残すが、画面には出さない。移行は変更履歴に残り、元に戻せる。

#### 計算仕様

記号: P = 価格、D = 営業日数（未入力なら30）、m = 目標利益率（未入力なら15%）、VC = 変動費/件、FC = 月額固定費の合計、IC = 初期費用の合計、u_s = シナリオ s の1日の販売数。

| 指標 | 式 | 計算できない条件と表示 |
|---|---|---|
| 変動費/件 VC | 金額行の合計 + Σ（%行 × P） | %行があり P がない → 「Needs price」 |
| 粗利/件 CP | P − VC | P がない → 「Needs price」 |
| 粗利率 | CP ÷ P | 同上 |
| 損益分岐の件数/月 BE_m | FC ÷ CP | FC がない → 「Needs monthly costs」。CP ≤ 0 → 計算しない。警告「Contribution margin is zero or negative. Review price or variable costs.」 |
| 損益分岐の件数/日 | BE_m ÷ D | 同上 |
| 損益分岐の売上/月 | BE_m × P | 同上 |
| 目標利益率を達成する件数/月 | FC ÷（CP − P × m） | CP − P × m ≤ 0 → 「This margin is not reachable: contribution margin is at or below the target」 |
| 目標利益率を達成する件数/日 | 上 ÷ D | 同上 |
| シナリオの件数/月 | u_s × D | u_s がない → その列は「Empty」（0 にしない） |
| シナリオの売上 | 件数/月 × P | |
| シナリオの変動費合計 | 件数/月 × VC | |
| シナリオの営業利益 | 売上 − 変動費合計 − FC | |
| シナリオの営業利益率 | 営業利益 ÷ 売上 | 売上 0 → 「—」 |
| 損益分岐の列 | u = BE_m ÷ D で同じ表を作る。営業利益は 0 | |
| 回収期間（月） | IC ÷ Expected の営業利益 | Expected の営業利益 ≤ 0 → 「Not recovered: Expected profit is zero or negative」（原本の「空欄にする」に代えて理由を出す）。Expected がない → 「Needs Expected sales」 |
| 単純 ROI（年） | Expected の営業利益 × 12 ÷ IC | IC がない・0 → 「Needs startup costs」 |

- 価格と費用は全シナリオ共通で、変わるのは販売数だけ。立ち上がり期間・税・割引は考えない（原本どおり）。
- **Capacity 警告**: Conservative / Expected / Strong のいずれかが Capacity Limit を超えたら「Strong exceeds capacity limit」。損益分岐の件数/日が Capacity Limit を超えたら「Break-even is above capacity」。
- **下限の伝播**: IC が下限（未入力・Unknown の行あり）のとき、回収期間は「9.2+ months」、ROI は「≤ 130.9%」と示す。
- **端数（原本どおり小数第1位）**: 計算の途中では丸めない。表示のときだけ四捨五入する。
  - 件数（損益分岐・目標利益率・シナリオの件数/月・件数/日）: 小数第1位（例: 6.9件/日）。入力した販売数は入力どおり
  - 金額: 整数。ただし変動費/件と粗利/件は小数2桁
  - 率（粗利率・営業利益率・ROI）: 小数第1位の %
  - 回収期間: 小数第1位の月
- 計算結果は保存しない（毎回計算する）。決定ログと版のスナップショットにだけ、その時点の値を残す。

#### 範囲

| 書き出し元 | 選べる範囲 | 取り込める項目 |
|---|---|---|
| 自己分析（10 / 11） | 全体、またはセクション（WHY〜ONE-SENTENCE）を複数 | 全設問 |
| 検証（13 / 11 / 14〜18） | 設問型のセクション（01 / 02 / 04 のパターン / 08 / 10）を複数 | 設問への回答だけ |
| プラン（20 / 21） | 全体、Part A、Part B、または項目を複数 | 文章の小項目（長文・短文） |

- 範囲の初期値は、書き出し元の画面（今のセクション、今の項目）。
- 「参考情報を含める」をオンにすると、取り込みの対象にならない情報（主要指標、確認項目の状態、競合の一覧、調査ログの要約、前提・リスク、プランなら検証の数字と表の小項目）を「Reference (read-only)」として末尾に付ける。表・数字・リストは書き出せるが、取り込みはしない。
- 書き出しは記録しない（変更履歴にも決定ログにも残らない）。

#### 設問 ID の付け方

- 形式: `{種類}.{セクション}.{キー}`。英大文字・数字・`_` だけを使う。
- 設問 ID はテンプレートの版をまたいで同じ問いを指す。運営者が版を公開した後は変えられない。版の移行（6.0.7）と AI 取り込みの照合に使う。

| 種類 | 形式 | 一覧 |
|---|---|---|
| 自己分析 | `SA.{セクション}.{連番}` | `SA.WHY.1–2`、`SA.BE.1–2`、`SA.DO.1–3`、`SA.GIVE.1–3`、`SA.HAVE.1–4`、`SA.INCOME.1–3`（Q15〜17、金額＋理由）、`SA.ENOUGH.1–4`、`SA.NOT.1–4`、`SA.NOW.1–5`、`SA.FINAL.1–5`、`SA.ONE.1`（計36） |
| 検証 01 | `V.01.{キー}` | `WHO` `WHY_THEM` `BEHAVIOR` `PROBLEM` `FREQUENCY` `SEVERITY` `PAYMENT` `SWITCHING` `NON_CUSTOMER` `PROOF` |
| 検証 02 | `V.02.{キー}` | `CATEGORY` `OCEAN` `WHY` `DRIVERS` `BARRIERS` `RED_1–4` `BLUE_1–3` `MARKET_SIZE` `REACHABLE` `SHARE` |
| 検証 04 | `V.04.{キー}` | `SURVIVOR_PATTERNS` `FAILURE_PATTERNS` |
| 検証 08 | `V.08.WORTH` | 「Is the return worth the capital and effort?」 |
| 検証 10 | `V.10.{キー}` | `WHY_WORK` `WHY_FAIL` `MUST_BE_TRUE` `BIGGEST_UNKNOWN` `BIGGEST_RISK` `BIGGEST_OPPORTUNITY` |
| プラン | `P.{2桁の項目番号}.{連番}` | 項目の中の小項目ごと。例: `P.01.1`（What is the business?）、`P.24.1`〜`P.24.3`（We proceed to launch if / We delay if / We stop if）、`P.30.1`（One-minute explanation）、`P.30.2`（Five-minute explanation）。小項目の一覧は 6.12 |

#### 取り込み先

取り込み先は、入ってきた画面で決まる（自分の自己分析 / ある検証 / あるプラン）。24 の ③ から入ったときは、書き出したときの範囲を初期値にする。

#### ① 貼り付け

- テキスト欄に貼り付けるか、`.md` / `.json` のファイルを選ぶ。
- 形式は自動で見分ける: JSON として読めて `format` が `moonx-reply` か `moonx-export` なら JSON、それ以外は Markdown。
- Markdown は `## [ID]` の見出しでブロックに分ける。見出しの前の文章や、ID のない見出しのブロックは「未振り分け」にする。
- 何も読み取れなかったら「No question IDs found」と、期待する書式の例を出す。貼り付け全体を1つの未振り分けのブロックとして次へ進むこともできる。

#### ② 振り分け

| ブロックの状態 | 条件 | 操作 |
|---|---|---|
| 振り分け済み | ID が取り込み先のテンプレートの版にあり、取り込める型（長文・短文・選択・金額＋理由） | 必要なら別の設問に付け替える |
| 未振り分け | ID がない、ID が取り込み先にない、または ID が範囲の外 | 設問を選ぶか、捨てる。選ばずに次へ進むと捨てる |
| 取り込めない | ID はあるが、表・数字・リストの項目（例: 調査ログ・費用・プランの表や数字の小項目） | 捨てるだけ（「Lists and numbers can't be imported」） |
| 重複 | 同じ ID のブロックが2つ以上 | どちらを使うか選ぶ |

#### ③ 差分確認

- 設問ごとに、今の回答と取り込む内容を並べ、変わった部分を強調する。
- 取り込む内容はその場で直せる。
- 設問ごとに「反映する」のチェック（初期値はオン）。内容が同じ設問は「unchanged」として折りたたみ、反映しない。
- **検証の回答で内容が変わったものは、F/A/U を「未分類」に戻す。** 差分確認の画面でその場で付け直せる（Fact を選ぶと M2 が開く）。付け直さなければ未分類のまま反映する。根拠の紐づけは消さずに残し、Fact に付け直すときにそのまま使える。
- 自己分析の金額の設問は、金額を数値として読む（通貨記号・桁区切りを取り除く）。読めなければ「Couldn't read the amount」と出し、直すまで反映できない。
- 選択の設問（02 OCEAN）は Red / Blue / Mixed のいずれか（大文字小文字は問わない）。それ以外は直すまで反映できない。
- 開いた後に他の人がその回答を変えていた場合は、「Current」に最新の内容を出し、「Updated by Kenji just now」と添える。

#### ④ 反映

- 「Apply n changes」で、チェックした設問をまとめて反映する。全部反映するか、全部反映しないかのどちらか（途中で失敗したら何も変えない）。
- 各変更は変更履歴に「AI 取り込み」として残る。
- 反映したら書き出し元の画面（10 / 11 / 13 / 20 / 21）へ戻り、「2 answers updated · 1 needs F/A/U」と出す。未分類が増えたら 13 の Next steps に出る。

#### 状態

| 状態 | 表示 |
|---|---|
| 振り分け済みが0件 | ③ に進めない。「Nothing to import」と ① に戻るボタン |
| 変更が0件 | 「No changes found」と閉じるボタン |
| 反映の失敗 | 入力を残して「Couldn't apply — Retry」 |
| Viewer | この画面に入れない |

### 6.10 14 調査ログ / 15 競合・代替 / 16 前提・リスク

#### 14 調査ログ（パターン D）

| 列 | 型 | 備考 |
|---|---|---|
| Date | 日付 | 既定は今日 |
| Topic | 短文 | 必須 |
| Observation | 長文 | 発見したこと |
| Source Type | 選択 | Google Maps / Reviews, Website, Social Media, Public Data, News / Report, Store Observation, Price Check, Other |
| Source URL | URL | 任意 |
| Supports check | 複数選択 | **裏付ける確認項目**: 地元の価格帯（Local price）/ 許認可（Permits）/ 需要・課題シグナル（Demand or problem signal）。確認項目の判定に使う。どれにも当てはまらなければ付けない |
| What It Supports | 長文 | 何を裏付けるか（自由記述） |
| Used as evidence | 自動 | 根拠として使っている項目の数と一覧 |

- 確信度（Confidence）は持たない（確信度は Assumption の側だけ。調査ログの信頼性は出典の種類と URL で判断する）。
- 一覧は裏付ける確認項目・出典の種類で絞り込み、日付順に並べる。行を押すと右（スマホは全画面）に詳細と「Used as evidence」の一覧を出す。
- 空の状態: 「Record what you observe, with sources. Others can check it later.」と + Add entry。

#### 15 競合・代替（パターン E）

- カードの項目: Name（必須）/ Type（Direct Competitor / Indirect Competitor / Substitute）/ Target Customer / Offering / Typical Price（金額）＋ Price note（例: per box）/ Strength / Weakness / Why Customers Choose Them / Why They Survive / 根拠（M2）。
- 見出しに「4 competitors · aim for 3–5」。
- Web は「Cards / Table」を切り替えられる。表は項目を行、競合を列にして見比べる。
- カードの下に Survivor Patterns と Failure Patterns の2つの設問（`V.04.SURVIVOR_PATTERNS` / `V.04.FAILURE_PATTERNS`、長文・F/A/U 付き）。
- 空の状態: 「List 3–5 competitors or substitutes. Include what people do today instead.」と + Add competitor。

#### 16 前提・リスク（パターン D）

- 上部のタブで Assumptions / Risks を切り替える。
- Assumptions の項目: Assumption（必須）/ Why We Believe It / Evidence（M2 の根拠＋自由記述）/ Confidence（Low / Medium / High）/ What Would Disprove It / Next Check。
- Risks の項目: Risk（必須）/ Probability（Low / Medium / High）/ Impact（Low / Medium / High）/ Why It Matters / Mitigation / How to Validate。
- Risks の並び順: Impact の高い順、同じなら Probability の高い順（Pitch Deck の Risks スライドもこの順）。手で並べ替えもできる。
- 空の状態: タブごとに説明と + Add。

14〜16 共通: 行数の上限なし。行の追加・編集は Web は右の詳細ペイン、スマホはボトムシート。削除は確認のうえで行い、変更履歴から戻せる。Viewer は読み取りだけ。

```
│ 状態                           │ セクション                     │
│  21 / 36 answered             │  WHY            2/2  ✓      → │
│  Shared with: (not shared)    │  BE             2/2  ✓      → │
│  Template v1                  │  DO             1/3         → │
│                               │  …                            │
│                               │  ONE-SENTENCE   0/1         → │
└───────────────────────────────┴──────────────────────────────┘
```

- 状態: 未着手（Not started）/ 回答中（In progress）/ 完了（Done）。
- **Continue**: 最初の未回答の問いを 11 で開く。セクションを押すと、そのセクションの最初の未回答の問いにフォーカスして開く。
- **Mark as done**: いつでも押せる。未回答があれば「5 questions are empty. Mark as done anyway?」と確認する。完了の後も編集でき、「Reopen」で回答中に戻せる。
- **共有（M6）**: 完了にした後で使える（「各自で完了させてから議論する」原則）。共有先は自分が Owner / Member として所属するワークスペースから複数選べる。共有先では Owner / Member が読める（Viewer は読めない）ことを M6 に明記する。共有をやめるのはいつでもできる。共有先には最新の回答が見える。
- 自己分析はワークスペースに属さないので、どのワークスペースから開いても同じ内容。
- 空の状態（未着手）: 「Answer 36 questions at your own pace. Only you can see your answers until you share them.」と [Start]。

#### 12 メンバーの自己分析（パターン D）

- 左に今のワークスペースの Owner / Member の一覧（共有済みの人は押せる。共有していない人は「Not shared」でグレー）。
- 右に選んだ人の自己分析を、セクションごとの読み物として表示（問い・回答。Q15〜17 は金額と理由）。各回答にコメントできる（PNL-1）。変更履歴は出さない。

### 6.17 26〜28 運営者の画面

#### 26 管理: テンプレート一覧（パターン D）

- 左に3つのテンプレート（自己分析 / 検証 / プラン）。右に選んだテンプレートの版の一覧（版番号・状態（下書き / 公開）・公開日時・公開した人・この版を使っている件数）。
- 操作: 「New draft from this version」（その版をコピーして下書きを作る）、下書きを開く（27）。下書きは1つのテンプレートに1つまで。
- 空の状態は無い（初期データで3つの v1 を公開済みにする）。

#### 27 管理: テンプレート編集（パターン D・ツリー）

- 左にセクション（プランは項目）と設問（プランは小項目）のツリー（並べ替え・追加・削除）。右に選んだものの編集欄。
- セクション: キー・タイトル・ガイダンス（プランは項目の1行の説明）。
- 設問: 設問 ID（公開後は変えられない）・タイトル・問い・EXAMPLE・ヒント・回答の型・選択肢（選択の型）・表の列（表の型）・表示する主要指標（検証の数字の型）・表示条件（例: 02 OCEAN が Red か Mixed のとき）・F/A/U を付けるか（検証）・下書きでコピーする元（プラン）。
- 検証のテンプレートだけ: 費用行の初期値（表ごとの行名とキー）、確認項目の基準値（競合の件数3、価格の入った競合2件、裏付ける確認項目タグの調査ログ1件 など）。
- プランのテンプレートだけ: 実行管理の初期行（マイルストーン・ローンチ・KPI）。
- すべて: AI 用の対話プロンプト（長文）。
- 操作: 自動保存（下書き）、プレビュー（11 の見た目）、「Publish as v{n}」（確認: 既存の回答は変わらないこと、利用者は M8 で移れることを示す）。公開済みの版は編集できない。
- 公開の前の検査: 設問 ID の重複、ID の形式、前の版から消えた ID（移行で引き継がれない回答が出ることを警告）。

#### 28 管理: ユーザーとワークスペース（パターン D）

- タブ: Users / Workspaces / Invitations。
- Users: 表示名・メール・登録日・最終利用日・所属ワークスペース数・状態（有効 / 停止）。操作: 停止 / 再開。運営者には中身（アイデア・回答）は見せない。
- Workspaces: 名前・Owner・メンバー数・アイデア数・最終利用日。
- Invitations: 招待の一覧と発行（メール、任意でワークスペースとロール）。取り消し・再送。

## 7. データモデル

論理設計。型は論理型（uuid / text / int / decimal / bool / date / timestamp / enum / json）。全テーブルに `id`（uuid）、`created_at`、`updated_at` を持つ（下の表では省略）。`deleted_at` を持つテーブルは論理削除で、変更履歴から戻せる。

### ER図

```
users ─┬─ N:M ─ workspaces            （中間: memberships。ロール owner / member / viewer）
       ├─ 1:1 ─ self_analyses ─┬─ 1:N self_analysis_answers
       │                       └─ N:M workspaces（中間: self_analysis_shares）
       └─ 1:N ─ notifications

workspaces ─┬─ 1:N invitations（運営者の招待は workspace なしも可）
            ├─ 1:N ideas ─┬─ 1:1 validations ─┬─ 1:N validation_answers
            │             │                   ├─ 1:N research_log_entries
            │             │                   ├─ 1:N competitors
            │             │                   ├─ 1:N assumptions
            │             │                   ├─ 1:N risks
            │             │                   ├─ 1:N cost_items
            │             │                   └─ 1:N economics_inputs（7つの入力。field_key で一意）
            │             │      evidence_links: validation_answers / cost_items / economics_inputs /
            │             │                      competitors / assumptions → research_log_entries（N:M）または URL
            │             ├─ 1:N business_plans ─┬─ 1:N plan_answers（小項目ごと）
            │             │                      ├─ 1:N plan_versions
            │             │                      └─ 1:N execution_items
            │             └─ 0..1 ideas（duplicated_from: 複製元）
            ├─ 1:N decision_log_entries（idea、business_plan、plan_version を参照）
            ├─ 1:N comments ─ 1:N comment_mentions
            └─ 1:N change_history（自己分析の履歴は workspace なし・本人のみ）

templates ─ 1:N template_versions ─┬─ 1:N template_sections ─ 1:N template_questions
                                   ├─ 1:N template_cost_defaults（検証）
                                   ├─ 1:N template_check_rules（検証）
                                   └─ 1:N template_execution_presets（プラン）
self_analyses / validations / business_plans ─ N:1 template_versions（作成時の版に固定）
```

### データのルール

- **数字の正は検証に置く。** プランは数字を持たず、検証を参照する。数字の違う案は「アイデアを複製」して別の検証にする。
- **テンプレートを改訂しても、既存の回答は作成時の版に固定する。** 最新版への移行は任意で、設問 ID が一致する回答を引き継ぐ。
- **変更はすべて履歴に残す。** 対象は自己分析・検証・プラン・実行管理。自己分析の履歴は本人だけが見られる。
- **決定ログは追記だけ。** 記録した判定・Go / No-Go・版の保存は編集・削除しない。
- **Fact には根拠が必須**（evidence_links が1件以上）。Assumption にだけ確信度を付ける。数字の Unknown は値を持たない。
- **選択肢の値は原本を踏襲する。** 判定 Proceed / Hold / Drop、市場の種類 Red / Blue / Mixed、確信度 Low / Medium / High、Can Reduce? Yes / Partly / No、競合の種類 Direct Competitor / Indirect Competitor / Substitute、出典の種類（14 の一覧）。
- **ワークスペースの通貨を変えても金額は換算しない。**
