# @moonx/ui-web

Web の部品（React Aria Components ＋ vanilla-extract。design-spec 4.5）。役割は [SDD 2章「リポジトリ構成」](../../docs/02-01_system-design-doc.md#リポジトリ構成) と [SDD](../../docs/02-01_system-design-doc.md) の ADR-025。

## 中身

- `src/index.ts`: 画面が読み込む入口。読み込むとテーマ（`@moonx/ui-tokens/theme.css`）・ページの土台・書体（`src/styles/`）も入る
- `src/components/`: design-spec 4.5 の部品。見た目は `*.css.ts` に書き、`@moonx/ui-tokens` の `vars`（semantic 層）だけを参照する。部品の文言（React Aria が持つ文言のうち上書きできるものを含む。SDD 9章「React Aria の文言」）は、`@moonx/i18n` のカタログから react-i18next の `useTranslation` で引く（ADR-026。引くネームスペースを渡し、キーは `components:…` の形のまま書く）。インスタンスは、アプリのルート（`apps/web/src/routes/__root.tsx`）が `I18nextProvider` で渡す共有のもの（`@moonx/i18n` の `i18n`。書式関数と同じ）で、言語が変わると部品も描き直す。部品のテストでは `src/test/setup.ts` が同じインスタンスを react-i18next の既定にする。部品の外で文言を作る関数は置かず、フックにする（`useFauLabel`・`internal/NavBadge.tsx` の `useNavItemName`）
- `src/layout/`: Flex・Stack・Grid・Container。間隔はトークンの名前（`gap="space-300"`）で、幅の段ごとの値（`{ mobile, tablet, desktop }`）も受ける
- `src/patterns/`: レイアウトのパターン A〜J の枠（design-spec 4.1）と、パターン C の外に置く設問の並び（`QuestionList`。15 の Survivor / Failure Patterns）。画面は中身を props（`header`・`blocks`・`list`・`filters`・`detail` など）で渡し、3つの幅の並びと、`docs/mockups` の列の幅・余白・比（06 `semantic.layout`）はパターンが決める。列の幅の上限は中身の幅で、ページの左右の余白はその外に足す（`patterns.css.ts` の `pageColumn`）。比の列（A の 7 : 5、J の 6 : 5）は flex の伸びで、D の左のペインは 5 / 11 の幅（380px 以上）で描く（CSS の `fr` は変数で書けないため）。主要な操作は、A・B・G はスマホで下部に固定し（`internal/frame.tsx` の `BottomBar`。スマホでは Button を XL にし、quiet でないボタンが幅を分け合う）、E・H・I はどの幅でもその場に置く（4.1）。密度は 4.4「密度とスケールの対応」のとおりパターンごとに決まる（A・D・E・F・I は regular、B・C・G・H・J は spacious）。spacious のパターンは `internal/Density.tsx` の `Density` で囲み、中の入力欄と Button に L を渡す（Form の中でも外でも。Form は `density` を渡さなければ周りの密度を取る。Checkbox・Radio・Switch は密度を受けず M のまま）。Dialog は `density`（M1〜M9 は spacious）で、AlertDialog は regular で囲み直す（重ねて出す部品は React の context で開いた所の密度を受け継ぐため）。幅で並べ替える所は、画面の見た目の順と文書の順（読み上げと Tab の順）をそろえる
- アプリの枠: `components/` の AppFrame・SideNav・TabBar・AlertBanner（ヘッダーの下の帯）・PageFrame・RouterProvider（design-spec 4.5・6.0.1）。SideNav と公開ページの三日月の印は `internal/BrandMark.tsx` が `@moonx/ui-tokens` の `ICON_SHAPES`（PWA のアイコンと同じ形）で描く。ページ全体がスクロールし、ヘッダー・サイドバー・TabBar は画面に留まる。AppFrame はヘッダーの高さとスマホの TabBar の高さを CSS 変数（`internal/frame.css.ts`）で中のパターンに渡し、パターンの下部に固定する操作（`internal/frame.tsx` の `BottomBar`・`FloatingAction`）は TabBar の上、キーボードが出ているときはその上に付く。AppFrame の外（PageFrame・確認用ページ）では、どちらも 0 になる。フォーカスで画面に入る入力欄がヘッダーと下の固定の操作に隠れないよう、`html` の `scroll-padding` も同じ高さにする。スマホのヘッダーは、← と戻り先の名前（か題）を「…」で切らずに「Saving…」「Saved」が入るかを ResizeObserver で測り、入らない間は印だけにする（ラベルは読み上げに残す。幅を測るための写しは、ヘッダーの外に出ない大きさの無い箱の中に置く）。AppFrame は本文（`main`）の幅とパネルの列にパネルがあるかを ResizeObserver で測り、デスクトップでパネルが本文を 06 `layout.two-column-min-width`（`@moonx/ui-tokens` の `twoColumnMinWidth`）より狭くしている間は、HubPattern・ListDetailPattern・WorksheetPattern にタブレットの並びを取らせ（`internal/frame.tsx` の `useTwoColumns`）、MetricGroup の `band` を 2×2 にする。`layout.presentation.two-column-min-width`（`presentationTwoColumnMinWidth`）より狭くしている間は、PresentationPattern にスマホの並びを取らせる（`useThumbnailColumn`。design-spec 4.1）。測った幅は描く前に反映する（`flushSync`）ので、狭まった2列は描かれない。本文の幅は `main` の先頭の高さの無い要素で測る（並びが変わると本文の高さが変わり、`main` を測るとブラウザが ResizeObserver の通知を積み残してエラーを出すため）。デスクトップではスクロールバーの溝を常に空ける（`scrollbar-gutter: stable`。スクロールバーの出入りで本文の幅が変わり、並びが行き来し続けないため）
- `src/internal/`: 部品の中だけで使うもの。`ResponsivePopover` は Popover・Menu・Picker・DatePicker・ContextualHelp の、タブレットの幅から上では Popover、下ではトレイになる重ね方（design-spec 4.5）。トレイの枠は `components/Tray.tsx` の `TraySheet`（公開する `Tray` はそれに dialog を足したもの）。`MoonMark` は月の印（4.4「状態の形」）のただ1つの描き方で、MoonGlyph と StatusLight が使う。`diff.ts` は DiffText の文字単位の差分、`slideUnits.ts` は Slide の寸法（06 `semantic.print`）をスライドの幅に対する割合にする関数、`scrollToFocusAnchor.ts` は QuestionCard を 06 `layout.focus-anchor` の高さへ送るスクロール。`frame.tsx` は AppFrame とパターンの受け渡し（ヘッダーにパターンの道具（11 の Focus のスイッチ）を置く場所、スマホでヘッダーの ← を一覧へ戻す ListDetailPattern の上書き、A・D・F が2列で並べられるかと I がサムネイルの列を出せるか（`BodyRoom`））と、`BottomBar`・`FloatingAction`・画面上部の帯（`Banners`。オフラインを先に並べる）、`NavBadge.tsx` は SideNav（等幅の数字）と TabBar（インクの札）の未読数。ほかにフィールドの共通の見た目・ラベルと説明とエラー・キーボードで隠れないようにする処理（4.3）・TextArea と MentionTextArea が入力に合わせて広がる処理・幅の段の判定（`useIsNarrow`・`useIsDesktop`）・macOS の判定（`platform.ts`。4.1 C の Ctrl+Option+↓ / ↑）
- `src/preview/`: 開発用の確認のページ（`/dev/components`。docs/03_dev-setup.md 3.3）。英語の文字列を直接持つ（SDD 9章）。`MockupScreens.tsx` と `screens/` は `docs/mockups` の11画面を部品で組み直したもので、`/dev/components?screen=s05-dashboard&theme=dark` のように開くとウィンドウいっぱいに1画面だけを描く（モックアップと並べて見比べるため。`e2e/mockup-screens.spec.ts` が値を測る）
- 書体: `src/styles/fonts.ts` が `@fontsource` の CSS を読み込む。woff の予備は `apps/web/vite.config.ts` が外し、woff2 だけを配る（ADR-018）

## テスト

Vitest ＋ Testing Library で書き、部品の操作は `@react-aria/test-utils` も使う（ADR-022）。`packages/` のほかのパッケージが使う Bun test とは別のツールなので、書き方が違う。axe の検査は部品のテストではなく E2E で行う。

- import: `import { expect, test } from "vitest"`（`bun:test` は使えない）
- 置き場所: 対象のファイルの隣に `*.test.tsx`
- 実行: `make test-web`（`apps/web` のテストと一緒に動く）
- 環境: happy-dom。設定は `vitest.config.ts`。幅は `src/test/helpers.ts` の `setPhoneWidth()` で変える（`matchMedia` が幅に合わせて変わる）
- happy-dom で動かない React Aria の操作: ツールバーやボタンのグループ・Tabs で ← を押して前の要素へ移る操作、トレイやダイアログやメニューを開いたときの中へのフォーカス（ComboBox のトレイの入力欄、DatePicker のカレンダーの日、AlertDialog の `autoFocusButton`、Menu の最初の項目）とそれに続くキー操作、日付の欄（DatePicker の月・日・年）への入力。これらは `e2e/components.spec.ts`（Chromium）で確かめる。重ねて出す部品の位置（トレイ・全画面のシート・中央のカード）と、開いた状態の axe の検査、タッチの長押し（Tooltip）も E2E で確かめる。jsdom は `make test-web` が使う Bun の実行環境では起動しない
- happy-dom に無いもの: `cqw` の長さ（捨てる）と並びの計算。スライドの文字の大きさがスライドの幅に対する割合になっていることは E2E で確かめる。AppFrame が本文の幅で A・D・F・I の並びを決める処理は、`components/frame.test.tsx` が ResizeObserver と `getBoundingClientRect` を差し替えて確かめ、実際の幅（1024px・1340px・1440px でパネルを開く）は E2E で確かめる
